## PART C: AUTHENTICATION FLOW

### Signup Flow (New Account Creation)

```
1. User visits /auth page
2. Clicks "Sign Up" tab
3. Fills form:
   - Name
   - Email
   - Password (min 6 chars)
   - Village
   - District
   - State
4. Clicks "Create account" button
   ↓
5. Frontend validates form (Zod schema)
6. Frontend calls: await supabase.auth.signUp({ email, password })
   ↓
7. Supabase validates:
   - Email format
   - Password strength
   - Email not already taken
8a. If invalid → Error shown → Stays on form
8b. If valid → Auth user created in auth.users
   ↓
9. Frontend creates profile record:
   await supabase.from('profiles').insert({
     id: user.id,
     name,
     email,
     location: village,
     district,
     state
   })
   ↓
10. Profile created successfully
11. Session automatically created by Supabase SDK
12. Session stored in browser (persistent)
13. Toast: "Account created successfully"
14. Navigate to /dashboard
15. Dashboard beforeLoad checks session → ✅ Allowed
16. User sees dashboard
```

### Login Flow (Existing Account)

```
1. User visits /auth page
2. Clicks "Login" tab
3. Fills form:
   - Email
   - Password
4. Clicks "Login" button
   ↓
5. Frontend validates format
6. Frontend calls: await supabase.auth.signInWithPassword({ email, password })
   ↓
7. Supabase validates credentials against auth.users table
8a. If invalid → Error: "Invalid email or password" → Stays on form ✅
8b. If valid → Session created
   ↓
9. Session stored in browser (persistent)
10. Toast: "Welcome back"
11. Navigate to /dashboard
12. Dashboard beforeLoad checks session → ✅ Allowed
13. User sees dashboard
```

### Route Protection Flow (Every Protected Page)

```
1. User tries to navigate to protected route (e.g., /dashboard)
2. Router calls beforeLoad() function
3. beforeLoad executes: await requireAuth()
   ↓
4. requireAuth() checks: await supabase.auth.getSession()
5a. If session exists:
    - Return session
    - Allow navigation
    - Component renders
5b. If no session:
    - Throw redirect({ to: '/auth' })
    - User redirected to login page ✅
    - Protected component does NOT render ✅
```

### Logout Flow

```
1. User navigates to /settings page
2. Clicks "Logout" button
3. Frontend calls: await supabase.auth.signOut()
   ↓
4. Supabase invalidates session
5. Session cleared from browser storage
6. Toast: "Logged out"
7. Navigate to /auth
8. User on login page
9. Try to access /dashboard → Redirected to /auth ✅
```

### Session Persistence Flow (Page Refresh)

```
1. User logs in successfully
2. Navigates around the app
3. Refreshes page (F5)
   ↓
4. App reloads
5. Supabase SDK checks for stored session
6a. If session exists and valid:
    - Session restored
    - User remains logged in ✅
    - Can access protected routes
6b. If session expired or missing:
    - Redirected to /auth
    - Must log in again
```
